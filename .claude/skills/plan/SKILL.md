# Plan генератор

Прочитай PRD из файла: $ARGUMENTS

Создай план реализации и сохрани результат в файл 'docs/plan-$ARGUMENTS.md' (используй перевод на английский и kebeb-case)

## Структура плана:

# Plan: {название фичи}

**PRD:** $ARGUMENTS
**Дата** {текущая дата}

## Фазы реализации

### Фаза 1: {Название}
**Цель:** Что дает эта фаза
**Затрагивает:** backend / frontend / database
**Задачи:**
- [ ] Задача 1
- [ ] Задача 2
**Когда готова:** Конкретный критерий

### Фаза 2: {Название}
...

## Правила разбивки на фазы
- Каждая фаза должна довать результат
- Фазы независимы, можно остановиться после любой
- Первая фаза как минимальный рабочий путь (Tracer Bullet)
- Не больше пяти задач в одной фазе
- бекенд и фронтенд одной фичи разной фазы

## Правила
- Читай PRD внимательно, пран должен показывать все критерии готовности
- Не добавляй задачи, которых нет в PRD
- Если PRD не полный, задай вопрос перед созданием плана
